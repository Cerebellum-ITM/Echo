# Architecture and Traps
> Boundaries, invariants, startup and root resolution, config/state storage, the prod-gate rule and the cross-cutting traps. Mandatory read after STATE; topic files own the details. Last verified: 2026-09-30.

## Shape

- One Go binary (module `github.com/pascualchavez/echo`, Go 1.25; `Makefile` builds and installs it as `echo_cli`). Four entry modes, all in `main.go`: interactive REPL (no args), one-shot `echo_cli <cmd> [args]` (script mode), recipe `echo_cli run <file>`, and `echo_cli connect …` (direct, handled before any project lookup).
- Stack (go.mod): lipgloss v1.1.0, bubbletea v1.3.6, huh v1.0.0, bubbles (pseudo-version), charmbracelet/log, BurntSushi/toml, coder/websocket (CDP), creack/pty, x/term. It is not "Charm v2". No git library: git, rsync, ssh, docker, psql, xmllint, bat are driven through `os/exec`.
- Echo is a thin orchestrator. It never reimplements Odoo or Postgres behaviour: it builds argv, runs it (locally via `docker compose exec`, remotely via `ssh`), and restyles the stream.

## Packages and boundaries

- Leaf packages import no other internal package: `config`, `docker`, `env`, `odoo` (Odoo CLI argv builders, `Conn` DB flags, version-aware), `odoolint` (offline XML checks), `depcheck` (symbols a module version drops, Unit 128), `project` (root discovery), `reverb` (HTTP client of the Reverb daemon), `theme`, `clipboard`. `banner` imports `theme`. `cmd` imports the leaves. `repl` imports `cmd` and some leaves. `main` imports all (checked by grep over imports, 2026-09-30).
- **`internal/cmd` cannot import `internal/repl`** (import cycle: repl imports cmd). Things that live in repl but are needed by cmd cross the boundary as package vars or opaque closures: `cmd.EchoVersion` (set in `main.go` from `repl.FullVersion()`, `internal/cmd/status.go`), `docker.LineTransform` (shell restyling closure threaded repl -> cmd -> docker), `cmd.PickOne` (export of the single picker), `cmd.OnRemoteResolved` (cmd -> repl callback with the resolved remote target, called by `resolveRemoteShell`/`resolveReverbShell`, set in `newSession`; unit 09 of the console run feed). New cmd-side needs of repl data follow the same pattern.
- Division of labour: `cmd.RunXxx(ctx, XxxOpts) (Result, error)` does the work and reports through callbacks (`Log`, `StreamOut`, `OnLine`); `repl` owns rendering, the dispatch switch, exit-code mapping and per-session state. The REPL holds no command business logic. Shape details: [code-standards](code-standards.md#command-shape).
- Odoo version differences are absorbed in `internal/odoo` builders (they take the version; `odoo.Major` parses `"19"`/`"19.0"`), never in the REPL. The flag set of `install`/`update`/`uninstall`/`test` is identical in 17/18/19; i18n branches at major >= 19. See [modules-and-odoo](modules-and-odoo.md).
- `compose exec` skips the Odoo image entrypoint, so Echo passes explicit `--db_host/--db_port/--db_user/--db_password` (`odoo.Conn`, values from the project's `.env` through `internal/env`); `Conn.Flags()` omits empty values (and callers default the port to 5432) because an empty `--db_port=` crashes the Odoo CLI.

## Invariants

1. **Stream, never buffer.** Subprocess output reaches the screen line by line (`docker.runStreamed`, `runSSHStream`, callbacks). Buffered transport (`runSSH`) is for short scalar queries only. Long remote streams use `runSSHStream`; binary payloads use `runSSHToFile`. See [remote-targets](remote-targets.md).
2. **No terminal means fail closed.** Anything that would show a picker or a confirm without a TTY returns `cmd.ErrNonInteractive` (exit 2) instead of blocking: the guard is `requireTTY(hint)` over the seam `stdinIsTTY` (`internal/cmd/interactive.go`). The escape hatch is always explicit: pass the missing argument or `--force`. Never add a prompt without that guard.
3. **Exit codes (one-shot and recipes)**: 0 ok, 1 execution error or counted ERROR lines, 2 usage / non-interactive guard, 3 cancelled (`internal/repl/repl.go:95-118`, `scriptExitCode`). `cmd.ErrQuit` maps to 0. The interactive REPL records the code per command but never exits with it.
4. **Echo's own state never lives in the user's repo.** All config and state sit under `~/.config/echo/` (and `~/.local/share/echo/`). Files Echo writes into the repo or cwd are outputs the user asked for: `./backups/` (db-backup/db-pull), `<addons>/<mod>/i18n/*.po`, `--log=.` transcripts. The one remote-side exception is `<remote_path>/.echo/` and `backups/code/` on the server, auto-ignored by git without touching the repo's `.gitignore` ([deploy-safety](deploy-safety.md)).
5. **Compose flavor is detected once** (`docker.DetectCompose` in `main.go` when `compose_cmd` is empty) and persisted in `global.toml`; never hardcode `docker compose` or `docker-compose`. A remote target uses the flavor from the server's own `global.toml` (default `docker compose` when absent), never the laptop's.
6. **Remote connection data comes from the remote profile, never local config**: container names, DB, stage, Odoo version, addons paths, compose flavor (`resolveRemoteShell` -> `remoteConnectTarget`, `internal/cmd/shell_remote.go`, `db_remote.go`). `resolveRemoteShell` is the single entry point of the remote surface (26 call sites, `grep resolveRemoteShell(` 2026-09-30). See [remote-targets](remote-targets.md).
7. **Validate before the first destructive step** so a late failure leaves no half-done state: the lint pre-flight runs before the first SSH call (`internal/cmd/deploy_lint.go`), the `op` (1Password) probe runs before `db-admin` writes its `UPDATE`. New destructive flows copy this ordering.
8. **Odoo-style output is the product idiom** (logger `echo.<cmd>[.<sub>]`, `key=value`, level chips); generic CLI decorations are rejected. Owner: [ui](ui.md).
9. **Styling goes through `internal/theme`** is the goal, not an enforced rule: `lipgloss.NewStyle()` appears 154 times outside `internal/theme` (grep, 2026-09-30; picker, repl, db). Do not add raw hex or ANSI in new code; do not assume the rule holds when refactoring.

## Startup and root resolution (`main.go`)

Order of the flow, in `main()`:

1. `cmd.EchoVersion` set. Leading `-C <dir>` / `--project-dir` extracted (must come first, like `git -C`). `--version`/`-v` print and exit; `--help`/`-h` become the `help` command. Both work anywhere.
2. `-C` value that is not a directory is tried as a **project alias**, then as a connect target whose `remote_path` is a local directory (`config.ResolveProjectAlias`). A real directory always wins over an alias.
3. `connect` is dispatched directly (`cmd.RunDirectConnect`) before any root lookup; failure is `log.Fatal` (exit 1).
4. Root: `project.FindRoot` walks up looking for `docker-compose.yml|yaml` only. If none is found: a **projectless one-shot** continues with `root = repoRoot(cwd)` (git top level, else cwd); any other one-shot exits 2 ("not inside a project"); the REPL exits with `log.Fatal`.
5. `config.Load(root)`; a `*config.ParseError` (global or project file does not parse) prints one `ERROR echo.config:` line on stderr and exits 2 before any REPL or command starts (`exitOnConfigError`, `main.go:173`; the same check guards `connect`). Any other load error falls back to `config.Defaults` with a warning. `BackfillProjectPath` stamps `project_path` into a pre-existing profile so the project is discoverable as a remote target. If `compose_cmd` is empty it is detected and saved.
6. `run` is routed here (not through `Registry`, and not in `projectlessOneShot`, so a recipe needs a compose project even when every step is remote, see [scripting](scripting.md)); any other one-shot must satisfy `repl.IsScriptCommand` (= `dispatchNames` minus `clear/exit/quit`), else exit 2. No arguments starts the REPL.

- **"Only runs inside a project" is false as a general rule.** `projectlessOneShot` (`main.go`) lists commands that run without a compose project: always for `help lint i18n-pull link doctor deploy push watch checkpoint actions promote logview report db-pull modules`; only with a remote flag (`--remote`, `--from`, `-E/--env`; `hasRemoteFlag`) for `shell shell-run up down stop restart ps logs sequence update test view compare db-admin`; `compare` also with `--targets` (`hasTargetsFlag`, `main.go:263`, checked for `compare` only).
- **Trap: a new remote-capable command must be added to `projectlessOneShot`**, otherwise it exits 2 from outside a compose directory. It was missed at first use for `logview --remote`, `db-pull` and `db-admin --remote` (Units 62, 98, 116). No test covers it.
- **A linked directory without compose is a first-class project.** Its key is `sha256(git top level)`. `repoRoot` also migrates state once: `config.MigrateProjectKey` renames the six per-project state locations (`projects`, `deploy-history`, `last-updates`, `last-sequences`, `checkpoints` `<key>.toml` files plus `cmd-logs/<key>/`) from the deepest ancestor that already holds state, only when the destination `projects/<key>.toml` is absent (so it is idempotent and never overwrites). `project.SameDir` compares through symlinks (macOS `/tmp` vs `/private/tmp`). Unit 115.

## Config and state storage

- `~/.config/echo/global.toml` (user-wide): `theme`, `logo`, `banner`, `compose_cmd`, `icons`, `log_db_max`, `[prompt]`, `[cmd_logs]`, `[checkpoint]`, `[push]`, `[deploy]`, `[promote]`, `[reverb]` (client credentials, **global only**, the token is a secret and must never be logged), `[connect_targets.<name>]`, `[project_aliases]`. The theme is the `theme` key here (no `.echo.toml` exists).
- `~/.config/echo/projects/<sha256(abs project root)>.toml`: `odoo_version`, `odoo_container`, `db_container`, `db_name`, `stage`, `addons_paths`/`addons_mode`/`conf_path`, `scripts_dir`, `compose_project`, `project_path`, `filestore_path`, plus tables `[connect]` (the link binding and its `git_*` keys), `[push]`, `[checkpoint]`, `[deploy]`, `[promote]`. Project values override global ones field by field except where a list is replaced wholesale (deploy actions, test modules): precedence table in [deploy](deploy.md).
- **`[reverb]` means two different things.** In `global.toml` it is the client's credentials table (url/token). In a project profile written on a server by Reverb it is a **marker** (`env_id`, `project`, `env`, `api_url`, `reverbMarkerFile`) with no secret. Do not conflate them. See [remote-targets](remote-targets.md).
- Per-project state, same key: `deploy-history/<key>.toml`, `last-updates/<key>.toml`, `last-sequences/<key>.toml`, `checkpoints/<key>.toml` (metadata only; the DB copies live on the server), `cmd-logs/<key>/<unix-millis>-<cmd>.json`. History and checkpoint maps are keyed again by `DeployTargetKey = sha256(ssh_host, remote_path)`, so staging is not prod.
- Global state: `connect-sessions/<target key>.toml` (minted Odoo session ids, plaintext, files are 0600), `run-logs/` (`last-run.json` is ONE global file, not per project, plus opt-in transcripts), `history` (REPL history, cap 1000). Outside the config dir: `~/.local/share/echo/connect-chrome` (persistent Chrome profile, `$ECHO_CONNECT_CHROME_PROFILE` overrides).
- **Config writers are load-modify-write, never rebuild-from-literal** (`SaveGlobal`, `SaveProject`, `savePromote`; `internal/config/config.go`, test `save_roundtrip_test.go`). They decode the current file and overwrite only the fields the `Config` owns, so unmodelled sections (`[reverb]`, `[checkpoint]`, `[push]`, `[deploy]`, `[promote]`, `icons`, project `[promote]`, `git_*` keys) survive. A rebuild-from-literal save silently erases them (every `--set-*` did, until Unit 118).
  - Owned fields are **always assigned, even to nil**, so "a section that returns to default is cleared". Do not change a save to write only non-default fields.
  - A section that exists in both global and project needs a `*Source` marker (`CheckpointSource`, `PromoteBranchSource`, `PromoteBaseSource`) so project-only content is re-emitted into the project file and global-only content is not copied down.
  - A new config section: load it in `Load`, either own it in the save (assign always) or leave it to the round-trip, and add it to the round-trip test.
- **Config files fail loudly; nothing writes over a file it could not read.** `Load`, `LoadGlobal`, `loadGlobalFile` and the read half of `SaveProject` go through `loadTOMLFile` (`internal/config/config.go:562`): a missing file is empty, one that does not parse is a `*ParseError` naming the file and the TOML position (`cannot parse ~/.config/echo/global.toml: line 2, column 8: …`). Every writer that reads first (`SaveGlobal`, `savePromote`, `SaveProject`, `SaveConnectTarget`, the alias writers) returns that error instead of writing (Unit 127). `BackfillProjectPath` still ignores a decode error, harmlessly: `Load` has already failed on the same file.
- **State files are best-effort but keep a corrupt copy.** Deploy history, checkpoints, last updates, last sequences and connect sessions read as empty when absent or corrupt, so a command never fails on them. Before overwriting, each writer calls `preserveCorrupt` (`internal/config/config.go:1130`), which renames a file that exists but does not decode to `<name>.corrupt-<YYYYMMDD-HHMMSS>` and logs a WARNING through the package's charmbracelet logger. All writes go through `writeAtomic` (tmp + rename, files 0600, dirs 0700).
- A missing local project profile means `stage = dev` (`Defaults`), i.e. the local prod gate never fires without `init`.

## Prod-gate rule

- A prod gate shows a red confirm when the stage is `prod` and `--force` is absent. Without a TTY it fails closed through `confirmProd` -> `requireTTY` (exit 2). One shared confirm: `confirmProd` (`internal/cmd/shell.go`).
- **Which stage decides**: a local action reads the project profile's `cfg.Stage` (`maybeConfirmProd` for shells, `maybeConfirmDockerProd` for `down`, i18n, db-neutralize for the active DB or prod). A remote action reads the **target's** stage from the server profile, `rsc.target.stage` (`confirmRemoteProd`, deploy, watch, connect). **Trap: the local `cfg.Stage` is irrelevant to a remote run**; using it asks nothing when you run from a dev checkout against prod (this was the `db-admin --from prod` bug, Unit 116).
- **An undeclared remote stage is prod.** `remoteConnectTarget` (`internal/cmd/db_remote.go:27`) keeps `dev`/`staging`/`prod` (case-insensitive, trimmed) and turns anything else, empty included, into `prod` with `stageDeclared=false`; every remote gate reads that normalized `target.stage`. Display (status line, pickers) keeps the raw server value. Rule and warning: [remote-targets](remote-targets.md#remote-prod-gate). Local config keeps "missing stage means `dev`" (below).
- Gating by **risk** instead of stage: `db-admin` asks on prod or when the credential is publicly known (`--insecure`), not on stage alone (Unit 116, `resolveAdminCredential`).
- Exceptions and strictness: read-only remote verbs (`logs`, `view`, `compare`, `db-pull`) never gate; remote `restart`/`stop` gate while local `restart` does not; `watch` needs `--force` to start against prod; `deploy --test` against prod needs `--force`. Details and the full list live with each command in [remote-targets](remote-targets.md) and [deploy](deploy.md).

## Cross-cutting traps

- **Flag parsers must consume the value of `--from`, `-E` and `--env`.** `remoteFlagsIn` only reads them; each command parser also has to swallow the pair, otherwise the target name leaks as a positional (`shell-run -E acme/main` tried to open that file; `parseDBArgs`, `internal/cmd/db.go`, reads it as the DB name). Applies to any new value-taking remote flag. Units 107, 116.
- **`ErrUsage` is mapped per REPL handler, not centrally.** `scriptExitCode` knows `ErrCancelled`, `ErrNonInteractive`, `ErrQuit`; it does not know `cmd.ErrUsage`. Each `sess.runXxx` handler must route it to `finalize(...)` plus `sess.exitCode = exitUsage`, otherwise a usage error becomes exit 1 plus a clipboard auto-copy (the `link` bug, Unit 106). See [code-standards](code-standards.md#new-command-wiring).
- **`exec.Command` without context is the exception**, not the rule: five sites (`internal/cmd/view.go:315`, `internal/cmd/connect_cdp.go:184`, `internal/odoolint/xmllint.go:93`, `internal/project/root.go:35`, `internal/clipboard/clipboard.go:77`). Rule and open question: [code-standards](code-standards.md#subprocesses).
- **Registry drift is a startup panic.** `Registry` and `commandFlags` are cross-checked in an `init()` in `internal/repl/commands.go` (duplicate names or a `commandFlags` key not in `Registry` panic the binary at start). It is the one sanctioned `init()`. Checklist in [code-standards](code-standards.md#new-command-wiring).
- **The version constant is a package var**, `Version` in `internal/repl/repl.go:30`, with build metadata appended by `FullVersion()` (`+<shortsha>[.dirty]` from the Makefile ldflags). Release rule in [operations](operations.md).
- **Interactive shells and Odoo's own ANSI**: `exec -t` and `docker compose logs` carry ANSI the plain log regex cannot match; Echo strips it before parsing. Details in [ui](ui.md).
- **`connect` forges sessions**: it mints an Odoo session by writing into the container's session store (no password, 2FA bypassed on purpose for dev use), and caches the session id on disk. The only brake is the prod confirm. Rationale: [decisions](../decisions.md). No command may print a minted session id.
- **Operations touching real servers** need the user's explicit go; see the live-verification ledger and its caveats in [operations](operations.md#live-verification-ledger).
